# v0.2 M2 — Draft/Seal Phase Implementation Plan

> **For agentic workers:** Execute task-by-task, TDD, one commit per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the founding phase (proposal D1/A3): a required `phase: draft | sealed` in `constitution.yml`; draft = fully mutable working set via new consent-gated verbs `adr edit` / `adr rm`; `constitution seal` writes the manifest baseline and flips the log to append-only forever; guard becomes phase-aware. Plus the two M1 deferrals (renumber rule-ref check, shared write-path prologue) and the §5 rule-length-warning hygiene.

**Architecture:** `internal/config` gains the required `phase` field. `regen` writes the manifest only when sealed (and deletes a stale one in draft, so crash recovery always converges). `guard` loads the config and, in draft, runs only id-uniqueness + parse + vocabulary (new violation kind `unknown_category`); sealed behavior is exactly today's. The three mutating verbs share one extracted validate-and-compose prologue. Sealed-phase semantics are untouched — v0.2 adds a phase *before* them, relaxing nothing after seal.

**Tech Stack:** Go 1.24+, urfave/cli v3, go.yaml.in/yaml/v3, testscript (txtar) e2e suite.

## Context for a fresh session (read first)

**Authority chain.** Design of record: `docs/proposal-v0.2-next-iteration.md` (§3 founding phase, §5 CLI hygiene). This plan implements **M2 only**; skills rewrite (M3) and doc reconciliation (M4) are out of scope. M1 (Rules grammar + per-rule fold) is merged (`3928b9b`); everything here builds on it.

**Locked decisions — do not re-litigate:**
- D1: draft phase is fully mutable **through the CLI**; no digest chain or frozen-field guard until seal. Seal flips to append-only forever; sealed semantics = exactly today's semantics.
- A3: `phase:` is **required** in `constitution.yml` — no absent-field defaulting (D4). Pre-v0.2 configs are invalid until the one-line field is added by hand (in-house migration).
- D4: no backward compatibility; goldens and the guard JSON schema change freely. Determinism + from-empty replay stay invariants.
- Consent is orthogonal to phase: every draft-phase write is still consent-gated (`--approve` for non-TTY).
- User-locked 2026-07-23: `adr edit` = **per-facet replace** (provided flags replace that facet, omitted facets keep); `adr rm` **leaves an id gap** (no auto-renumber; `renumber` stays the explicit escape hatch); PR **merges on green** (squash, like #13).

**Implementation decisions made in this plan (flagged for review, reversible until built):**
- **Draft repos have no manifest.** Draft-phase regen skips `manifest.Write` and *removes* a stale `.manifest.sha256` if present. This makes every crash window convergent: seal writes the manifest *before* flipping the config, so a crash between the two leaves a draft repo whose next regen deletes the orphan manifest and whose seal re-run completes cleanly.
- **Guard in draft:** id-uniqueness + parse (a malformed ADR stays an exit-2 error, as today) + vocabulary check, reported as a new violation kind `unknown_category`. No git legality, no manifest cross-check. Explicit `--base`/`--merge-base` in draft is an exit-2 error (git legality has no meaning before seal); `--no-git` is a no-op. Text output labels the mode `draft`. Sealed guard is unchanged (vocabulary stays regen's job there, as today).
- **Facet detection via `cmd.IsSet`**, not zero-values. Facets: `--title` (renames the file to the new slug, id kept), `--source`, `--body-file` (replaces the ENTIRE body incl. the `## Rules` section's presence/absence — the exact shape `adr new` accepts), `--rule` (replaces only the Rules section; combined with `--body-file` under the same mutual-exclusion rule as `new`), `--supersedes-rule`/`--removes-rule` (replace the whole list; a single empty-string value clears it, empty mixed with non-empty = error). `--new-category` supported as in `new`. At least one facet flag required. `date` is **not** editable and is kept as-is (the record's original date; an edit is a draft revision, not a new decision). `status`/`supersedes`/`superseded-by` are never edit facets — they belong to supersede/deprecate/rm.
- **`adr edit` targets accepted ADRs only** (revising a superseded/deprecated record is theater; error says so).
- **`adr rm` reference rule:** refuse when any *other* ADR cites the id in `supersedes-rules`/`removes-rules` (error lists the referrers — those lists are editable, fix them first) or when the target is itself superseded (`A.superseded-by = B`: rm B first). **One heal case:** rm'ing an ADR that *supersedes* another (rm B where `B.supersedes = A`) is the draft-phase "undo a supersede": B is deleted AND A is restored (status → accepted, `superseded-by` cleared) in the same operation. Any status is rm-able (subject to the reference rule).
- **Seal sequence:** render + full pre-seal checklist (all long-rule warnings, 200-line warning, resurrection warnings) → "last cheap edit" notice → consent gate → `manifest.Write` → flip `phase: sealed` via `persistConfig` → regen. Idempotent at every crash point. Sealing a sealed repo = error.
- **§5 hygiene:** the per-rule length warning moves out of bare `regen` — it fires (a) in `new`/`edit`/`supersede`, scoped to the ADR just written, and (b) in `seal`, across all ADRs, as the checklist. The 200-line constitution warning and the fold/resurrection warnings stay in regen (they describe the projection, not one record).
- **`renumber`** (M1 deferral): the "is it referenced?" refusal extends to rule refs — any other ADR whose `supersedes-rules`/`removes-rules` cites `<old-id>/…` blocks the renumber. (Refuse, not rewrite — same conservative contract as the existing supersedes check.) Phase-agnostic, as today.

**Key code facts (verified 2026-07-23, do not re-derive):**
- `internal/config/config.go`: `Config` struct + `validate()`; consent/sourceTracking already default-and-validate there. `phase` slots in beside them but with NO default.
- `cmd/constitution/regen.go`: `regenAt` → `regenCore` (render → write constitution.md → `manifest.Write` → fold warnings → 200-line warning → `warnLongRules`). Manifest write and warnLongRules both live here today.
- `cmd/constitution/guard.go` does **not** load `constitution.yml` today; `internal/guard.Run(Options)` takes only Root/Base/MergeBase/NoGit. Phase awareness = load config in the cmd layer, pass phase (and vocabulary) into `Options`.
- `internal/guard/guard.go`: `allKinds` is schema-locked — `json_test.go TestKindEnumLockstep` forces the JSON-schema fixture + all-kinds golden to move together when `unknown_category` is added.
- `internal/manifest`: `Write(adrDir, adrs)` is the whole baseline op; seal calls exactly this.
- `cmd/constitution/writepath.go`: `mutContext`/`openRepo`/`gate`/`readBody`/`composeRulesSection`/`bodyLabel`/`ruleRefFlags`/`resolveNewCategories`/`parseLog`/`preflightFold`/`appendCategories`/`persistConfig` all exist — edit reuses all of it. `persistConfig` is how seal flips the phase.
- `runNew` / `runSupersede` share a ~50-line validate-and-compose prologue (readBody → mutual-exclusion → compose → label → ValidateBody → validateSource → ruleRefFlags ×2) — Task 3 extracts it before edit becomes a third copy.
- `cmd/constitution/renumber.go`: refusal loop checks `a.Supersedes == oldID || a.SupersededBy == oldID`; rule-ref extension goes right there. File-rename crash pattern (write new → checkpoint → remove old) is the model for edit's `--title` rename.
- `constitution/.state` is the skills fan-out drift ledger — **unrelated** to the manifest/digest machinery; M2 does not touch it.
- `patch` package has `Supersede`/`SetID`; rm's heal case needs the inverse (restore accepted + drop `superseded-by`) — add `patch.Unsupersede` (or equivalent) with the same status-line-only discipline.
- **Verify during implementation (small, cheap):** (1) `adr.NextID` must be max+1, not count+1, or rm's id gap breaks id allocation; (2) `deprecate` flips only the target's own status (no partner link), so rm of a deprecated ADR has no heal case; (3) CI's guard job builds the in-PR source (so the same-PR own-config migration stays green).
