## Ground truth the tasks rely on (verified against main, 2026-07-23)

- CLI surface after M1+M2 (from `--help`, authoritative):
  - `adr new`: `--title --source --body-file --approve`,
    `--rule "<category>/<slug>: <text>"` (repeatable; composed into `## Rules`;
    mutually exclusive with a body-file that carries its own `## Rules`),
    `--supersedes-rule` / `--removes-rule "ADR-NNNN/<category>/<slug>"`
    (repeatable), `--new-category` (repeatable). **`--category` no longer
    exists.** Same rule-surface flags on `supersede`.
  - `adr edit <id>` (draft only): per-facet replace — `--title` renames the
    file, `--body-file` replaces the ENTIRE body incl. Rules
    presence/absence, `--rule` replaces only the Rules section, ref-list
    flags replace wholesale with `""` to clear.
  - `adr rm <id>` (draft only): refuses while referenced
    (supersedes-rules/removes-rules or a superseding successor); removing a
    superseding ADR restores its target to accepted; ids are not renumbered.
  - `constitution seal`: pre-seal rule-length checklist → consent → manifest
    baseline → `phase: sealed` → regen. `--approve` on every mutating verb is
    the non-TTY consent path.
  - `init`: `--founding-file --target --skills-tree --category --consent
    --force`; founding-file grammar = one principle per `## <title>`; a
    `## Rules` heading immediately after a principle carries that principle's
    rules in the `### <category>` / `#### <slug>` grammar; no `## Rules` ⇒
    catalog-only record. Init writes `phase: draft` and says so.
  - Guard is phase-aware: draft = parse + id-uniqueness + vocabulary only
    (`unknown_category`); `--base`/`--merge-base` in draft = exit 2.
- Starter vocabulary is code: `cmd/constitution/init.go:23`
  `starterCategories = ["architecture","code-style","process","testing","security","data"]`.
- Skills are embedded (`embed.go` → `//go:embed skills`) and fanned out by
  `init`/`regen`; **no code change needed to ship skill-text edits**, but
  `init_skills_real_bodies.txtar` greps one distinctive phrase per skill:
  `Priority hierarchy \(highest wins\)` (gov), `The consent checkpoint`
  (adr-draft), `Check a plan against this repo` (plan-gate), and
  `cat constitution/constitution.md` (gov). Keep the phrases or update the
  txtar in the same commit.
- `constitution-init` is bootstrap-only: ships via the Claude Code plugin
  (`.claude-plugin/plugin.json`, currently `0.1.0`), never fanned into the
  governed repo.
- `deviation.json` cites `adrId` at whole-ADR granularity and its validator is
  untouched by v0.2 — plan-gate needs terminology updates only.
- The repo's own log: 12 record-only ADRs, `phase: sealed`, guard clean.
  D2's preamble already renders (landed with M1); spec §1 already carries the
  purpose text? — verify in T7; spec §4.1 still shows the OLD single
  `## Rule` grammar and `category:` frontmatter; `implementation-plan.md`
  §2–§3 still describe v0.1.

### T2 — `constitution-init` SKILL.md rewrite (the big one)

Rewrite `skills/constitution-init/SKILL.md` as an explicitly **interactive,
multi-turn, staged** founding interview. Required content, in order:

1. Keep: frontmatter (name/description/disable-model-invocation — description
   updated for the staged flow), the already-initialized check, the
   install-prebuilt-release block.
2. **Elicitation contract, stated first and bindingly:** the skill MUST
   interview and MUST NOT write the founding file (or run any command) until
   the human has confirmed the content. No formalize-before-elicit.
3. **Front-loaded projection model** (before category selection): explain
   that `constitution.md` sections = categories, one ADR can carry rules in
   several categories (they fan out to their sections), rules are
   individually addressable as `ADR-NNNN/<category>/<slug>`, and record-only
   principles never render.
4. **Opinionated question catalog** replacing the bare starter-list offer —
   each question maps to a category and to concrete config where applicable:
   - How do we track issues? (→ `sourceTracking` config + process rules)
   - What agents do we build for? (→ `--target` claude/agents/both)
   - Do we do spec-driven development, with which framework? How do we
     manage our spec? (→ process rules; e.g. spec-lifecycle adoption)
   - What's the project structure? (→ architecture rules)
   - How do we solve recurring problems — mapping, testing, error handling,
     persistence? (→ the "how" rules; a rule may delegate to a skill, e.g.
     "hexagonal per kentra-skills:java-hexagonal" — named as an *example*,
     neutral mechanism)
   - Category vocabulary: propose the (new) starter list, human trims/extends.
5. **Rules-vs-bets triage:** for every founding principle, THREE-way call —
   standing rule / point-in-time record / **unvalidated bet** (an assumption
   research could kill). Bets become record-only ADRs or a parked list —
   never clauses welded into a rule-bearing structural ADR; they are
   revisited in stage 3 after research.
6. **Staged founding roadmap (A4):** (1) purpose + very-high-level design
   ADRs → (2) research the technology bets → (3) technical-architecture ADRs
   informed by that research → `constitution seal` when the bets are
   validated. Init covers stage 1 and ends **in draft**: stop selling
   finality; close by saying the constitution stays draft — `adr edit` /
   `adr rm` remain cheap — until an explicit seal, and state the seal
   criteria.
7. **Founding-file grammar** updated to the real one: `## <title>` + body,
   optional `## Rules` immediately after with `### <category>` /
   `#### <slug>` entries (1–3 line imperative texts); example showing one
   principle with rules in two categories + one record-only principle.
   `--principle` is not offered (founding-file only — implementer's choice
   per proposal A2, and the file form is the only one that can express
   categories).
8. **Consent mechanics:** under `strict` in a non-TTY shell the interactive
   `[y/N]` always fails; `--approve` with the harness permission prompt as
   the human gate is the sanctioned path; never pre-approve or route around
   the prompt.
9. Keep the honest `sourceTracking` v1 note (init still writes `type: none`;
   post-init config edit is the path), the show-command-before-running rule,
   run-once rule, verify/hand-off section (guard clean, cat constitution.md,
   grow via adr-draft/gov), and the Never list — updated for v0.2 (draft
   phase exists; never hand-edit ADRs; never seal without the human).

### T3 — `adr-draft` SKILL.md update

- **Settledness gate, first section after the intro:** if the decision
  emerged from brainstorming or a sketch, confirm it is settled before
  drafting. Signal words that mean NOT settled: "brainstorm", "thoughts?",
  "how could we", "something like". Ask, don't assume.
- Grammar: replace the `## Rule` single-section instructions with the
  `## Rules` h3/h4 grammar (categories from the vocabulary, kebab slugs,
  1–3 line imperative texts, multi-category allowed); `--rule
  "<category>/<slug>: <text>"` as the flag alternative (mutually exclusive
  with a body-file carrying `## Rules`); `--category` flag is GONE — remove
  it from the command template; `--new-category` only with explicit say-so.
- Per-rule retirement: introduce `--supersedes-rule` / `--removes-rule`
  (`ADR-NNNN/<category>/<slug>`) for retiring individual prior rules; whole
  `supersede` stays for fully-dead decisions; note the resurrection rule
  (superseding an amender resurrects what it retired — re-retire what you
  don't want back; regen warns).
- Phase awareness: in **draft** phase a wrong recent ADR can be fixed with
  `adr edit` / `adr rm` (cheap, consent-gated); once **sealed**,
  supersede/deprecate are the only paths. Point at phase in
  `constitution.yml`.
- Consent: keep 'The consent checkpoint' section (fan-out grep) and add the
  `--approve` non-TTY mechanics as in T2.

### T4 — `constitution-gov` SKILL.md update

- Open with the purpose framing (D2, mirrors the rendered preamble): the
  constitution is the source of truth for the HOW so requirements stay
  functional.
- Update the projection description: curated = rule-bearing ADRs; rules are
  per-category h3/h4 entries addressable as `ADR-NNNN/<category>/<slug>`;
  a rendered rule may be retired later by an amending ADR without the file
  changing.
- Document retirement + **resurrection semantics (A7)**: fold honors
  retirement directives only from currently-accepted ADRs; superseding an
  amender resurrects what it retired; a superseding ADR must re-retire what
  it does not want back.
- Phase note: in draft, the log is a mutable working set (edit/rm via CLI,
  still consent-gated) and guard checks parse+vocabulary only; after seal it
  is append-only forever and the amend-only-through-the-flow rules apply
  with full force. Keep both grepped phrases (`Priority hierarchy (highest
  wins)`, `cat constitution/constitution.md`).
- Consent mechanics one-liner (`--approve` + permission prompt).
